milestones

What Equity can do now, step by step.

  1. October 21, 2026 · resume and long contextcapability

    Chats that resume at once; keys and values on storage

    A chat can save the model's state on the phone: on Flash Next a resumed 140-token chat showed its first token after 8.7 s instead of 27.8 s, with the same tokens. Sparse-attention keys and values can live in a file on storage, at no measurable cost on a 4K window. The recurrent state is now read in place, which saves about 10 ms per token in the profile.

  2. October 20, 2026 · the expert packspeed

    Flash Next at 2.99 tok/s, up from 1.5

    A speculative pool, a two-layer lookahead, demanded reads first, then an expert pack: 46 GB of experts moved in place on the phone, reversibly, so each expert is one read. With a quantized lookahead router the engine decodes at 2.99 tok/s on average, with the same tokens in every arm.

  3. October 19, 2026 · the 120B-class modelcapability

    125B parameters, 78.9 GB, running in the app

    Qwen3.8-Flash-Next adds 512-expert routing, a file-mapped n-gram table and support for its hyper-connection residual. The owner's first app screenshot reports 1.8 tok/s over 252 tokens, with the first token after 6.1 s. Host exactness checks pass.

  4. Equity's first beyond-RAM runexactness

    A model twice the device's memory, running on it

    The first target checkpoint — twice the phone's visible RAM — streams on a stock Android device at ~3.7–3.9 GiB RSS, the shared weights read once at load in 4.3 s, the experts as demanded. On every verification fixture, streamed output is bitwise identical to resident inference.

  5. the 5 tok/s barrierspeed

    5.54 tok/s — from 2.52, with identical tokens

    The slot-addressed expert cache — reusable pages hooked into GGML's expert matrix product — took decode from 5.05 to 5.54 tok/s mean, and the whole climb from 2.52. In short runs on a cool phone the experimental target is met; over minutes, power and heat set the speed, and that is measured too.

  6. past 5 tok/s in the appspeed

    7.4 tok/s in the app; the 4-bit reference above 5

    A per-operation profile showed a token spending more time waiting than computing. Six threads, misses overlapped with the experts already in memory, the lookahead on its own thread and a lighter interface took the engine from 5.45 to 8.22 tok/s and the app to 7.4 (2.7-bit) and 5.1 (4-bit) in short answers on a cool phone — tokens unchanged.

  7. long context, unlockedcapability

    262k context, needle at 7,857 tokens found

    Context and generation caps removed, with the KV cache counted in memory admission. A 7,857-token needle-in-a-haystack prompt is answered correctly; a 3,803-token prompt prefills 3.2× faster (521.6 s → 164.4 s) with bit-identical logits.

  8. speculation, made profitablekernels

    MTP went from a loss to a tie or a gain

    Exact 2×2 dotprod tiles for Q5_K / IQ2_XXS / IQ3_XXS — bit-identical to single-column kernels — cut a 2-token batch from ~1.9× to 1.2–1.4× a single token. Expert pairing in MUL_MAT_ID makes tokens that choose the same expert share one decode of its weights.

  9. the first yardstickquality

    26/27 on both builds — quantization on trial

    A 27-item, automatically checked set (Italian, instructions, reasoning, code, knowledge, long context): UD-IQ2_M and UD-Q4_K_M both score 26/27 — they miss the same discount-and-markup item — and the 2.7-bit build is ~33% faster. A first signal: a larger set is required before it can replace the reference.

where this goes

The queue is ordered by measured bottleneck.

01

Energy per token — heat lowers the big cores' clocks within seconds; less energy per token keeps them higher

02

Flash Next, sustained — long runs, energy, and a quality evaluation of its 2-bit build

03

Long context on storage — decoding with thousands of tokens of keys and values in a file

04

Expert kernels — the 2-bit expert formats are compute-bound, well below the K-quants' bandwidth

05

A larger quality set — before a 2-bit build can replace a reference
