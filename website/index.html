the idea

Mixture-of-experts models are mostly dormant weights.

In a MoE transformer, each token activates only a handful of experts per layer. The rest of the model just sits there. A large MoE model might therefore never need most of its weights at any given instant — and flash storage can keep up, if you read exactly the right bytes at exactly the right time.

Equity keeps the shared attention and shared-expert weights resident, and streams the routed experts from the phone's storage on demand. The model is never shrunk, distilled or approximated to fit: what runs is the published model, bit for bit.

how it works

Shared weights stay resident. Experts stream.

One token touches forty layers in a fixed cycle. Equity turns that pattern into a pipeline: predict, read, compute — overlapped, zero-copy, and exact.

01Resident core, streamed experts

About 2.4 GiB of attention and shared weights live in RAM. The routed experts — 9–19 GB — are read on demand into a bounded set of reusable, page-aligned slots, found through a hook added to GGML's MUL_MAT_ID.

02Zero-copy direct I/O

Expert banks sit at file offsets congruent to their memory addresses, so direct reads land in place — no bounce buffer, no page faults on reload. memmove fell from 7.9% to 1.7% of samples; page faults from ~21,000 to 19 per token.

03Router lookahead

Applying layer l+1's router to layer l's state predicts the next experts with 81.8% accuracy and cut decode I/O wait by 40% in its first version — the next layer is being read while the current one computes.

04A cache that respects the cycle

Expert access is cyclic across layers, so a global LRU scores 0% hits at any budget. Per-layer quotas make the cache work at all — up to 91% hit rate on the target with a 2 GiB budget.

05Kernels for this CPU

Exact 2×2 dotprod tiles for Q5_K / IQ2_XXS / IQ3_XXS, bit-identical to single-column; an i8mm (USMMLA) microkernel for tiled prefill, up to 3.8× faster on IQ3_XXS; a NEON GEMM where SVE builds fell back to scalar attention; expert pairing, so tokens choosing the same expert decode it once.

06Context bounded by the model

The engine's own 8,192-token cap is gone; admission counts the KV cache from GGUF metadata (~22 KiB per token). Context now runs to the model's full 262,144 tokens — memory admission, not an arbitrary constant.

milestones

Things that now exist, and did not before.

  1. first beyond-RAM runexactness

    A model twice the device's memory, running on it

    The first target checkpoint — twice the phone's visible RAM — streams on a stock Android device at ~3.7–3.9 GiB RSS, the shared weights read once at load in 4.3 s, the experts as demanded. On every verification fixture, streamed output is bitwise identical to resident inference.

  2. the 5 tok/s barrierspeed

    5.54 tok/s — from 2.52, with identical tokens

    The slot-addressed expert cache — reusable pages hooked into GGML's expert matrix product — took decode from 5.05 to 5.54 tok/s mean, and the whole climb from 2.52. In short runs on a cool phone the experimental target is met; over minutes, power and heat set the speed, and that is measured too.

  3. long context, unlockedcapability

    262k context, needle at 7,857 tokens found

    Context and generation caps removed, with the KV cache counted in memory admission. A 7,857-token needle-in-a-haystack prompt is answered correctly; a 3,803-token prompt prefills 3.2× faster (521.6 s → 164.4 s) with bit-identical logits.

  4. speculation, made profitablekernels

    MTP went from a loss to a tie or a gain

    Exact 2×2 dotprod tiles for Q5_K / IQ2_XXS / IQ3_XXS — bit-identical to single-column kernels — cut a 2-token batch from ~1.9× to 1.2–1.4× a single token. Expert pairing in MUL_MAT_ID makes tokens that choose the same expert share one decode of its weights.

  5. the first yardstickquality

    26/27 on both builds — quantization on trial

    A 27-item, automatically checked set (Italian, instructions, reasoning, code, knowledge, long context): UD-IQ2_M and UD-Q4_K_M both score 26/27 — they miss the same discount-and-markup item — and the 2.7-bit build is ~33% faster. A first signal, kept honest by its own footnote: a larger set is required before it can replace the reference.

  6. the instrument panelmethod

    Measurement tooling that makes the gains believable

    Bit-for-bit checks of streamed against resident inference; an automatically checked quality set; energy per token from the battery counter; A/B runs cooled to skin temperature between arms. Negative results — WFE waits, layer-skip speculation, wider prefetch — are documented, not discarded.

Honesty notes

Research preview. All numbers are measured on the current reference device — a stock Android phone — and recorded in results/. The 5 tokens/s sustained goal is an experimental target, never a promise. Quality, context and capabilities are not traded for speed.

Standing on

Built on llama.cpp / GGML, pinned with two recorded patches. The streaming design was informed by antirez's ds4 and published expert-offloading work. Development is AI-assisted; every claim is tied to a measurement record.
