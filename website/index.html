The model is bigger than the phone's memory. It runs anyway.

Equity runs mixture-of-experts models larger than the device's memory — offline, on stock Android — by streaming from storage only the experts each token needs. Streamed output is bitwise identical to running the same model file in memory: streaming adds no approximation. No cloud, no account.

the idea

Mixture-of-experts models are mostly dormant weights.

In a MoE transformer, each token activates only a handful of experts per layer. The rest of the model just sits there. A large MoE model therefore never needs most of its weights at any given instant — and flash storage can keep up, if you read exactly the right bytes at exactly the right time.

Equity keeps the shared attention and shared-expert weights resident, and streams the routed experts from the phone's storage on demand. Streaming never approximates: what runs is the published quantized build (GGUF), with the same results as if it were held in memory. Choosing a smaller quantization is a separate, quality-tested decision.

The idea is not new. Apple's LLM in a Flash, Mixtral offloading, EdgeMoE, PowerInfer-2 and antirez's ds4 all read weights from flash on demand. Equity's part is an exact implementation of it for one model family on a stock phone, measured step by step.

Exact by construction

Streamed inference is bitwise identical to resident inference, checked on the host, in a Linux container with real O_DIRECT, and on the phone. Every optimization is either bitwise exact or differs only in float rounding, with output tokens compared on the device.

◍

Off-grid by default

Stock Android, no root, no thermal overrides. No accounts, no telemetry, no silent downloads: the network is used only for a model download you start, a resumable, checksum-verified step. Prompts, answers and chats never leave the phone.

⌁

Measured, not promised

Every figure ties to a record in the repository; app observations are labeled separately from benchmarks. A/B runs cooled between arms, energy read from the battery counter, an automatically checked quality set. Negative results are written down, not deleted.

how it works

Shared weights stay resident. Experts stream.

A token passes through every layer in a fixed order, and each layer asks for a few experts. Equity turns that pattern into a pipeline: predict, read, compute — overlapped, zero-copy, and exact.

01Resident core, streamed experts

Attention, shared experts and the other shared weights stay in RAM. The routed experts — most of the file — are read on demand into a bounded cache of reusable, page-aligned slots, which GGML's expert product reads in place through a hook added by Equity.

02Zero-copy reads

Direct I/O bypasses the page cache and lands each expert straight in its slot: no bounce buffer, no page faults on reload. An optional expert pack, built in place on the phone and fully reversible, stores each expert in one piece, so a single read fetches it whole.

03Router lookahead

On its own thread, a predictor applies the next layers' routers to the current state, so the experts a token will need are already being read while the current layer computes. Predictions only decide what to read early: routing itself stays exact.

04Misses that do not stop the token

Experts already in memory are computed first, and each thread waits only for the part of a missing expert it reads. Demanded reads go ahead of speculative ones, and speculative reads never evict cached experts.

05Kernels for this CPU

Exact multi-column dot-product tiles for speculative verification, an i8mm microkernel for prompt processing, and runtime selection of the right instruction-set variant. Each kernel is checked against the reference before it is used.

06Context bounded by the model

The window is limited by the model's trained length and the memory available, not by a constant. For sparse-attention models the attention keys and values can live in a file on storage, with only the blocks attention selects kept in memory.

the app

A private assistant that lives on the phone.

The Equity app puts the engine behind a chat. Everything it does happens on the device; the only network traffic is a model download you start yourself.

Chats that stay on the phone

Conversations are saved in the app's private storage, with photos, camera captures, text files and PDFs as attachments. Delete one chat or all of them at any time.

Answers in the background

Answers keep being written while you use other apps, with a notification when they are done. Markdown and LaTeX are rendered, and models with a thinking mode show their reasoning apart from the answer.

Pick up where you left off

A chat can keep the model's state on the phone. Coming back to it continues at once, without reading the whole conversation again. It is opt-in per chat and deleted with the chat.

The context at a glance

A small gauge beside Send shows how much of the loaded window a chat uses. The window sizes itself from free memory, up to the model's full length.

Downloads you control

Models download in the app, resumable and checksum-verified, or come from a file you pick. Deleting a model deletes everything that belongs to it.

For the curious

An optional GPU mode reads long prompts and images on the phone's GPU. Directional steering, an experimental per-chat control, applies a model-specific vector to every answer.

One model family, from small to huge.

Honesty notes

Research preview. Device benchmarks, owner-reported app observations and host checks are labeled separately; records live in the repository. The 5 tokens/s sustained goal for models beyond RAM is an experimental target, never a promise. Quality, context and capabilities are not traded for speed.

Standing on

Built on llama.cpp / GGML, with pinned revisions and recorded patches. Streaming from flash builds on antirez's ds4, LLM in a Flash, Mixtral offloading, EdgeMoE and PowerInfer-2. Development is AI-assisted; every claim is tied to a measurement record.
